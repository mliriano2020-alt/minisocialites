No worries — this is a super common hiccup when publishing a site on GitHub Pages. A 404 “File not found” almost always means one of three things went wrong, and we can fix all of them quickly.

Let’s walk through the exact checklist so you can spot what happened.

✅ 1. Make sure your file is named EXACTLY index.html

GitHub Pages only loads a file called:

Code
index.html

Common mistakes:

  • Index.html (capital I — won’t work)

  • index.HTML (wrong extension)

  • index.htm (missing “l”)

  • home.html (GitHub won’t load it)

  • index (1).html (happens if you downloaded twice)

👉 Go to your repository → Files → confirm the name.

✅ 2. Make sure the file is in the ROOT of the repository

Your index.html must be here:

Code
your-repo-name/
    index.html   ← must be here

NOT inside:

  • a folder

  • /docs (unless you set Pages to use docs)

  • /main/index.html

  • /website/index.html

If it’s inside a folder, GitHub Pages won’t find it.

✅ 3. Make sure GitHub Pages is pointing to the right branch

Go to:

Settings → Pages

You should see:

  • Source: Deploy from a branch

  • Branch: main

  • Folder: / (root)

If it says:

  • /docs

  • or a different branch

  • or “None”

…then GitHub Pages won’t find your file.

✅ 4. Make sure the site finished building

After enabling Pages, GitHub takes 30–60 seconds to publish.

Check:

Settings → Pages → Build status

If it says:

  • “Queued”

  • “Building”

  • “Processing”

…wait a moment.

If it says:

  • ❌ “Failed”

…then the file is missing or misnamed.
